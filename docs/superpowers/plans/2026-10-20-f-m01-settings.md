# 설정 화면 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 홈에서 설정 화면을 열어 펫 종류와 이번 달 예산을 바꾸고, 로그아웃(서버·토큰·SDK)하거나 확인 후 회원 탈퇴(서버·토큰·SDK 연결 끊기)한다.

**Architecture:**
- 서버 호출과 토큰 처리는 API 클라이언트에 둔다(`logout`, `deleteMe`).
- SDK 로그아웃·연결 끊기는 `social-credential.ts`에 두고 실패를 삼킨다.
- 이 둘을 엮어 상태를 `signedOut`으로 바꾸는 일은 세션 provider가 맡는다(`signOut`, `deleteAccount`).
- 화면은 새 라우트 `settings/index`·`settings/budget` 두 개다. 온보딩 예산 화면과 예산 변경 화면은 입력 UI 컴포넌트를 공유한다.

**Tech Stack:** Expo SDK 58, Expo Router 58(`Stack.Protected`, `useFocusEffect`, `router`), React Native 0.88, TypeScript 6, Jest 30 + `jest-expo` + RNTL 14(`render`·`fireEvent`는 async), Maestro, 개발용 앱(`com.altair.petgyebu`).

**Spec:** `docs/superpowers/specs/2026-10-20-f-m01-settings-design.md`

## Global Constraints

- 새 의존성 없음. 백엔드 변경 없음.
- 문구:
  - 홈 링크: "설정"(role `link`)
  - 헤더: "설정", "예산 변경"
  - 섹션 제목: "펫", "{YYYY}년 {M}월 예산"(`monthTitle`), "계정"
  - 펫 선택지: `PET_LABELS`의 "고양이"·"강아지"(role `radio`)
  - 버튼: "변경", "저장", "로그아웃", "회원 탈퇴"
  - 공급자: "카카오로 로그인됨"·"Google로 로그인됨"
  - 탈퇴 확인 창: 제목 "회원 탈퇴할까요?", 본문 "지출과 예산 기록이 모두 삭제되고 되돌릴 수 없어요.", 버튼 "취소"(cancel)·"탈퇴"(destructive)
  - 탈퇴 시간 초과: `'탈퇴됐는지 확인하지 못했어요. 다시 시도해 주세요.'`
  - 그 밖의 오류는 `errorMessage()`를 쓴다.
- 로그아웃은 실패하지 않는다. 서버 401, 네트워크 오류, 시간 초과에도 토큰을 지우고 SDK 로그아웃을 시도한 뒤 `signedOut`이 된다. 확인 창은 없다.
- 탈퇴는 서버가 204를 줄 때만 토큰을 지우고 SDK 연결 끊기를 시도한 뒤 `signedOut`이 된다. 실패하면 로그인 상태를 유지하고 오류를 보여 준다.
- SDK 호출 규칙:
  - 로그인한 공급자만 부른다(카카오 `logout`/`unlink`, 구글 `GoogleSignin.signOut`/`revokeAccess`).
  - 오류는 삼킨다.
  - 가짜 로그인 모드(`__DEV__ && devLoginId`)에서는 부르지 않는다.
- 예산은 현재 월(`currentMonth()`)에만 PUT한다. 입력 규칙은 `parseBudgetInput`·`formatAmountInput`이다. 서버 400 `month`는 `refreshStage()`, `amount` 필드 오류는 그 문구로 처리한다.
- 토큰·SDK 응답을 로그나 오류에 남기지 않는다. 라우트 파일만 `src/app/`에 둔다. 테스트는 `__tests__/`에 둔다. 오류 문구를 쓰는 테스트는 기존 패턴대로 두 SDK를 `jest.mock`한다.
- 코드 작성 시 `.agents/skills/karpathy-guidelines/SKILL.md`를 따른다. Expo API는 SDK 58 문서로 확인한다. lint 규칙을 끄지 않는다. 커밋은 Conventional Commits 형식에 작성 모델의 `Co-Authored-By` 줄을 붙인다.
- 검사: `npm run lint`, `npm run typecheck`, `npm test`, `npx expo export --platform ios`.

## Review Focus

- 로그아웃 중 서버가 응답하지 않음(시간 초과) → 10초 뒤 로그인 화면으로 간다. 로그인 상태에 갇히지 않는다(Task 1 테스트).
- 이미 다른 기기에서 로그인해 리프레시 토큰이 무효인 상태에서 로그아웃 → 401이어도 로그인 화면으로 간다(Task 1 테스트).
- 탈퇴 요청이 시간 초과 → 로그인 상태를 유지하고 "탈퇴됐는지 확인하지 못했어요…"를 보여 준다. 토큰은 남는다(Task 1 + Task 3 테스트).
- 펫 저장 실패 → 선택이 이전 펫으로 돌아오고 오류가 보인다. 그사이 두 선택지는 잠긴다(Task 3 테스트).
- 예산 변경 화면을 연 채 달이 바뀐 뒤 저장 → 400 `month`, `refreshStage()` 호출(Task 2 테스트).

### Task 1: 로그아웃·탈퇴의 API·SDK·세션 처리

**Files:**

- Test: `__tests__/api-client-test.ts`, `__tests__/social-credential-test.ts`, `__tests__/session-provider-test.tsx`

**Interfaces:**
- Produces (`client.ts`):
  - `api.logout(): Promise<void>`
    - 저장된 리프레시 토큰이 있으면 `POST /auth/logout {refreshToken}`를 보낸다(인증 헤더 없이, `send(..., false)`).
    - 응답과 예외는 모두 무시한다.
    - 그다음 메모리의 액세스 토큰을 비우고 `tokenStore.clear()`를 부른다.
    - `onSessionExpired`는 부르지 않는다. 예외를 던지지 않는다.
  - `api.deleteMe(): Promise<void>`
    - `request('DELETE', '/users/me')`. 성공하면 액세스 토큰을 비우고 `tokenStore.clear()`를 부른다.
    - 실패하면 예외를 그대로 던지고 토큰은 남긴다.
    - 401이면 기존 `request`의 갱신 흐름을 탄다. 갱신에 실패하면 기존대로 `expire()`가 세션을 끝낸다.
- Produces (`social-credential.ts`):
  - `signOutSocial(provider: Provider, isDev: boolean = __DEV__, devId: string | null = devLoginId): Promise<void>`
  - `unlinkSocial(provider: Provider, isDev: boolean = __DEV__, devId: string | null = devLoginId): Promise<void>`
- Produces (세션 컨텍스트):
  - `signOut(provider: Me['provider']): Promise<void>`: 실패하지 않는다. 끝나면 상태가 `signedOut`이다.
  - `deleteAccount(provider: Me['provider']): Promise<void>`: 서버가 실패하면 예외를 던지고 상태를 그대로 둔다.
  - `'KAKAO'|'GOOGLE'`은 provider 내부에서 `'kakao'|'google'`로 바꾼다.

- [ ] **Step 1: `bootTestRun`에서 계약 확인**
  - `ok:<새 id>`로 로그인한 뒤 `POST /auth/logout {refreshToken}` → 204인지 본다.
  - 같은 토큰으로 다시 보내면 401인지 본다.
  - 새로 로그인한 뒤 `DELETE /users/me` → 204, 이후 `GET /users/me` → 401인지 본다.
  - 결과를 보고서에 적는다. `api-spec.md`와 다르면 멈추고 보고한다.
- [ ] **Step 2: 실패하는 테스트**
  - `logout`
    - 리프레시 토큰 `r1`이 저장돼 있으면 `POST {base}/auth/logout`, 본문 `{"refreshToken":"r1"}`, Authorization 헤더 없음.
    - 204 → `clear` 호출. 401 → `clear` 호출, 예외 없음.
    - fetch reject(네트워크) → `clear` 호출, 예외 없음.
    - 토큰이 `null` → fetch 호출 없이 `clear`.
    - 로그아웃 뒤 다른 요청에 Authorization 헤더가 없다.
  - `deleteMe`
    - 204 → `DELETE {base}/users/me`, `clear` 호출.
    - 500 → `ApiError(500)`를 던지고 `clear`를 부르지 않는다.
    - 시간 초과(가짜 타이머) → `RequestTimeoutError`, `clear`를 부르지 않는다.
  - `signOutSocial`
    - `'kakao', false, null` → 카카오 `logout`만 부른다.
    - `'google', false, null` → `GoogleSignin.signOut`만 부른다.
    - SDK가 reject해도 resolve한다.
    - `'kakao', true, 'u1'` → 아무 SDK도 부르지 않는다.
  - `unlinkSocial`: 같은 네 경우를 카카오 `unlink`, 구글 `revokeAccess`로 확인한다.
  - 세션
    - `signIn` 뒤 `signOut('KAKAO')` → `signedOut`이 되고 `/auth/logout`이 호출된다.
    - `deleteAccount('GOOGLE')`에서 서버가 500 → 상태가 `signedIn:*`로 유지되고 예외가 난다.
    - 서버가 204 → `signedOut`.
