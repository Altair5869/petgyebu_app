# F-M03 지출 입력·이번 달 내역 설계: 지출 입력 → 월 목록 → 홈 갱신

- 작성일: 2026-10-18
- 브랜치: `feature/F-M03-expense-entry-list`
- 관련 기능: F-M03(수동 지출) 중 생성·현재 월 목록, F-M06(현재 월 홈) 갱신
- 기준 문서: `docs/00-renewal-development-guide.md` 3·5절(우선), `docs/02-requirements-features.md` F-M03, `docs/03-user-flow.md` 2·5절, `docs/api-spec.md` 지출 API

## 1. 목표와 범위

사용자가 홈이나 이번 달 내역에서 지출을 기록하면, 이번 달 내역에 나타나고 홈의 사용 금액·사용률·잔액·펫 상태가 바뀐다.

**포함**

- 지출 입력 화면: 금액·날짜·카테고리·메모, `POST /expenses`
- 이번 달 내역 화면: `GET /months/{현재월}/expenses` 커서 무한 스크롤
- 홈: "지출 기록하기"·"이번 달 내역 보기", 화면 포커스 시 다시 조회

**제외**

- 지출 단건 조회·수정·삭제(다음 브랜치). 이번에는 내역 항목을 눌러도 동작하지 않는다.
- 과거 월 내역·월 선택(F-M05에서 통계와 함께)
- 데이터 캐시 라이브러리(TanStack Query 등). 포커스 시 다시 조회로 충분하다. 캐시·미리 불러오기가 필요해지면 다시 검토한다.

## 2. 구조

새 의존성은 없다. 날짜 선택기는 이미 설치된 `@expo/ui`의 `@react-native-community/datetimepicker` 호환 컴포넌트를 쓴다(정확한 import 경로·props는 SDK 58 문서와 설치된 타입으로 확인).

```
src/app/
  _layout.tsx                (수정) ready guard에 expenses/new, expenses/index 추가. 두 화면만 기본 헤더 표시
  index.tsx                  (수정) "지출 기록하기"·"이번 달 내역 보기", 포커스 시 다시 조회
  expenses/new.tsx           지출 입력
  expenses/index.tsx         이번 달 내역
src/api/
  types.ts                   (추가) ExpenseCategory, Expense, ExpensePage
  client.ts                  (추가) createExpense(body), getMonthExpenses(month, cursor?)
src/hooks/
  use-month-expenses.ts      월 목록 상태(첫 로딩·추가 로딩·오류·재시도·마지막 페이지), 늦은 응답 무시
src/lib/
  expense.ts                 카테고리 이름·순서, 메모 검증, 목록 행 제목·보조 정보
  money.ts                   (수정) 금액 파싱을 예산·지출이 공유(빈 값 문구만 다름)
  month.ts                   (추가) 서울 기준 오늘(YYYY-MM-DD), 날짜 표시("10월 17일")
src/components/
  expense-row.tsx            목록 한 줄
```

## 3. 화면 이동과 데이터 흐름

```
홈(index) ──"지출 기록하기"──▶ 지출 입력(expenses/new) ──저장──▶ router.back()
   │                                    ▲
   └──"이번 달 내역 보기"──▶ 이번 달 내역(expenses/index) ──"지출 기록하기"──┘
```

- 두 화면은 루트 Stack의 `ready` guard 안에 둔다. 펫·예산이 없으면 들어갈 수 없다.
- 헤더: 홈은 지금처럼 없음. 지출 입력 "지출 기록", 이번 달 내역 "이번 달 내역"(뒤로 가기 포함).
- **저장:** `POST /expenses` 본문 `{ amount, expenseDate, category, memo }`. 카테고리를 고르지 않으면 `OTHER`를 명시한다. 메모가 비었거나 공백만이면 `null`. 성공(201)하면 `router.back()`.
- **다시 조회:** 홈과 이번 달 내역은 Expo Router `useFocusEffect`로 화면이 포커스될 때마다 다시 조회한다.
  - 홈: `GET /home`. 이미 표시 중이면 로딩 화면 없이 값만 바꾼다. 기존 앱 활성화 시 다시 조회는 유지하거나 포커스 조회와 합친다(동작이 같으면 하나로).
  - 내역: 커서를 버리고 첫 페이지부터 다시 조회한다(지출 생성 뒤 커서를 버리는 규칙을 만족).
- **무한 스크롤:** `limit` 20. 목록 끝에 닿으면 직전 응답의 `nextCursor`를 그대로(URL 인코딩) 보낸다. `nextCursor: null`이면 더 요청하지 않는다. 추가 로딩 중에는 중복 요청하지 않는다.
- **늦은 응답:** 다시 조회를 시작할 때마다 요청 세대 번호를 올리고, 이전 세대의 응답은 버린다.
- **`INVALID_CURSOR`:** 첫 페이지부터 다시 조회한다.

## 4. 날짜

- 기본값은 서울 기준 오늘. 선택 범위는 2000-01-01 ~ 서울 기준 오늘.
- 선택기가 돌려준 날짜는 화면에 보이는 연·월·일 그대로 `YYYY-MM-DD`로 바꾼다.
- 기기 시간대가 서울과 달라 서버가 미래 날짜로 거절(400 `expenseDate`)하면 날짜 칸 아래에 서버 메시지를 보인다.

## 5. 화면

화면 문구와 카테고리 이름은 초안이다. 문서에 있는 이름은 `OTHER` = 기타뿐이다.

| 코드 | 이름 |
|---|---|
| `FOOD` | 식비 |
| `CAFE` | 카페 |
| `TRANSPORT` | 교통 |
| `SHOPPING` | 쇼핑 |
| `HEALTH` | 건강 |
| `LIVING` | 생활 |
| `OTHER` | 기타 |

### 지출 입력 (`expenses/new`)

- 금액: 숫자 키패드, 입력 중 쉼표. 비어 있으면 "금액을 입력해 주세요", 1 미만·100,000,000 초과면 "1원부터 1억 원까지 입력할 수 있어요".
- 날짜: 오늘로 채운 `@expo/ui` 날짜 선택기.
- 카테고리: 7개 칩(고정 코드 순서). 처음엔 선택 없음, 다시 누르면 해제. 선택 없이 저장하면 `OTHER`.
- 메모: 선택, 최대 100자(유니코드 코드 포인트, 이모지 1자). 넘으면 "메모는 100자까지 입력할 수 있어요".
- 저장 버튼: 아래쪽, 키보드 위로 올라온다(F-M01 예산 화면과 같은 `KeyboardAvoidingView`). 금액이 유효하고 메모가 100자 이하일 때만 활성. 저장 중에는 로딩·비활성, 중복 요청 없음.

| 결과 | 처리 |
|---|---|
| 201 | `router.back()` |
| 400 `fields`(`amount`·`expenseDate`·`category`·`memo`) | 해당 칸 아래에 서버 메시지, 입력값 유지 |
| 네트워크 오류·500 | "서버에 연결할 수 없어요. 다시 시도해 주세요.", 입력값 유지 |

### 이번 달 내역 (`expenses/index`)

- 위쪽: "{YYYY}년 {M}월"과 "지출 기록하기" 버튼.
- 행: 메모가 있으면 제목 = 메모(한 줄 말줄임), 보조 = "{M}월 {D}일 · {카테고리}". 메모가 없으면 제목 = 카테고리, 보조 = "{M}월 {D}일". 금액 "{N}원"은 항상 표시.
- 항목을 눌러도 동작하지 않는다(수정은 다음 브랜치).

| 상태 | 표시 |
|---|---|
| 첫 로딩 | 가운데 로딩 |
| 빈 목록 | "아직 기록한 지출이 없어요" + "지출 기록하기" |
| 첫 페이지 실패 | 연결 오류 문구 + "다시 시도" |
| 추가 로딩 중 | 목록 아래 작은 로딩 |
| 추가 로딩 실패 | 기존 항목 유지, 목록 아래 "다시 시도" |
| 마지막 페이지(항목 있음) | 목록 아래 "모든 내역을 불러왔어요", 더 요청하지 않음 |

### 홈 (변경)

- "지출 기록" 칸에 "지출 기록하기" 버튼과 "이번 달 내역 보기". 사용 금액이 0원이면 기존 "첫 지출을 기록해 보세요" 안내도 함께 보인다.
- 포커스 시 다시 조회해 지출 저장 뒤 사용 금액·사용률·잔액·펫 상태가 바뀐다.

### 공통

- 401은 API 클라이언트가 처리한다(갱신 실패 시 로그인 화면).
- 토큰·요청 본문을 로그에 남기지 않는다.

## 6. 테스트

| 대상 | 경우 |
|---|---|
| `lib/expense` | 메모 있음·없음의 제목·보조 정보; 메모 검증(공백만 → `null`, 100자 통과, 101자 거부, 이모지 1자); 카테고리 이름 7개와 순서 |
| `lib/money` | 금액 파싱 공유: 기존 예산 테스트 유지, 지출 빈 값 문구 |
| `lib/month` | 서울 기준 오늘(UTC 15:00 경계), "10월 17일" 표시 |
| `api/client` | `createExpense` 본문; `getMonthExpenses`의 `limit=20`과 커서 URL 인코딩 |
| `use-month-expenses` | 첫 페이지; 다음 페이지 이어 붙이기; 마지막 뒤 요청 없음; 추가 로딩 실패 시 항목 유지·재시도; 다시 조회 시 커서 버림; 다시 조회 중 늦은 이전 응답 무시; `INVALID_CURSOR` → 첫 페이지 |
| 지출 입력 화면 | 날짜 기본값 오늘; 카테고리 미선택 → `OTHER`; 공백 메모 → `null`; 메모 101자 → 저장 비활성; 400 필드 메시지·입력 유지; 두 번 눌러도 요청 1번; 성공 → `router.back()` |
| 이번 달 내역 화면 | 빈 목록; 첫 페이지 실패·재시도; 행 표시 |
| 홈 | 포커스 시 다시 조회; 두 버튼의 이동 경로 |

## 7. 완료 조건

1. `npm run lint`, `npm run typecheck`, `npm test`, CI, `npx expo export --platform ios` 통과.
2. 브랜치 전체 최종 검토(`app-qa`)와 지적 반영.
3. iOS 시뮬레이터(iPhone 18 Pro, iOS 27.0) + `bootTestRun` + Maestro. 예산 300,000원인 새 계정 사용. 확인하지 못한 시나리오는 PR에 "미확인".

   | # | 시나리오 | 기대 결과 |
   |---|---|---|
   | 1 | 홈 → 지출 기록하기 → 12,000원·카페·"라떼"·오늘 → 저장 | 홈 "288,000원 남았어요"·"사용률 4%". 내역에 "라떼"·"{M}월 {D}일 · 카페"·"12,000원" |
   | 2 | 카테고리·메모 없이 5,000원 저장 | 내역 제목 "기타", 보조 정보 날짜만 |
   | 3 | 150,000원 추가(합계 50% 이상) | 홈 "고양이 · 주의" |
   | 4 | 로컬 DB에 지출 25건 준비 | 20건 표시 → 스크롤 시 나머지 → "모든 내역을 불러왔어요" |
   | 5 | 날짜 선택기로 지난달 날짜 선택 후 저장 | 홈·이번 달 내역 변화 없음, DB에 지난달 행 |
   | 6 | 금액 비우기, 메모 101자 | 저장 비활성과 안내 문구 |
   | 7 | 백엔드 중지 상태로 내역 열기 → 실행 → 다시 시도 | 오류 화면 → 목록 |

4. `develop`으로 PR. 기능 ID, 사용한 API(`POST /expenses`, `GET /months/{month}/expenses`, `GET /home`), 확인 기기, 실제 검사 결과, 남은 제한(수정·삭제는 다음 브랜치, 과거 월 목록은 F-M05)을 적는다.
