- 관련 기능: F-M05(월별 상세 통계), F-M03(수동 지출) 중 과거 월 수정·월 이동, F-M06(현재 월 홈) 진입점
- 기준 문서: `docs/00-renewal-development-guide.md`(우선), `docs/02-requirements-features.md` F-M05·F-M03, `docs/03-user-flow.md` 3절, `docs/api-spec.md` 통계 API
- 이전 작업: `2026-10-19-f-m03-expense-edit-delete-design.md`(이번 달 수정·삭제. 과거 월 수정과 월 이동은 이번으로 미룸)

## 1. 목표와 범위

사용자가 한 달을 정리하거나 지난달과 비교할 때(사용자 확인: 둘 다) 월을 넘겨 가며 그 달의 총 지출, 카테고리별 비중, 전체 내역을 본다. 화면을 열면 **총 지출이 가장 먼저 눈에 들어와야 한다**(사용자).

**포함**

- 월별 통계 화면: 월 넘기기, 요약 카드, 카테고리 비중, 전체 지출 내역(무한 스크롤)
- 기존 "이번 달 내역" 화면을 이 화면으로 **대체**(사용자 결정). 홈의 진입점이 이 화면을 이번 달로 연다
- 과거 월 지출의 수정·삭제와 날짜를 다른 달로 옮기는 수정(F-M03 이전 작업에서 미룬 것)

**제외**

- 지난달 대비 차이 표시("지난달보다 +32,000원"). 월을 넘겨 직접 비교하면 충분하다(사용자 결정)
- 과거 월 예산 수정(문서 기준 조회만)
- 펫 이미지·상태(통계 화면 어느 달에도 없음, 문서 기준)
- 차트 라이브러리. 비중 막대는 기본 `View`로 그린다

**실패로 보는 것**

- 총 지출보다 다른 숫자가 먼저 눈에 띄는 배치
- 미래 월로 넘어갈 수 있는 것
- 예산이 없는 달에서 오류나 0%가 보이는 것(미설정으로 보여야 함)
- 월을 빠르게 넘길 때 이전 달 응답이 늦게 도착해 다른 달 숫자가 섞이는 것
- 날짜를 다른 달로 옮겨 저장했는데 옮겨 간 달이 아닌 화면으로 돌아오는 것

## 2. 백엔드 확인 결과 (2026-10-19, `bootTestRun`)

`GET /months/{month}/stats`가 `api-spec.md`와 일치한다.

| 경우 | 응답 |
|---|---|
| 이번 달, 예산 300,000원, 지출 4건 | `{"month":"2026-10","budgetAmount":300000,"spentAmount":26000,"expenseCount":4,"usagePercent":8.6,"budgetBalanceAmount":274000,"categories":[{"category":"CAFE","spentAmount":16000,"expenseCount":2,"sharePercent":61.5},{"category":"FOOD",…,"sharePercent":30.8},{"category":"OTHER",…,"sharePercent":7.7}]}` |
| 예산 없는 지난달, 지출 1건 | `budgetAmount`·`usagePercent`·`budgetBalanceAmount`가 `null`, 나머지 정상 |
| 지출 0건 | `spentAmount: 0`, `expenseCount: 0`, `categories: []` |
| 미래 월, 1999-12 | 400 `INVALID_REQUEST`, `fields: [{field: "month"}]` |

`sharePercent`는 반올림, `usagePercent`는 버림이며 앱은 받은 값을 그대로 쓴다(앱에서 다시 계산하지 않음).

## 3. 화면 이동

```
홈 ──"월별 통계"──▶ 월별 통계(이번 달) ──행 누름──▶ 지출 수정
                     │  ▲                              │
                     │  └── 저장: 수정한 날짜의 달로 ───┤
                     │  └── 삭제: 보던 달 그대로 ───────┘
                     └──"지출 기록하기"(이번 달일 때만)──▶ 지출 입력
```

- 홈의 "이번 달 내역 보기" 링크를 "월별 통계"로 바꾼다(문구는 내 판단). 기존 `expenses/index` 라우트는 이 화면으로 대체한다. 라우트 이름·파일 위치는 구현자 판단.
- 헤더 제목 "월별 통계"(내 판단).
- 진입 시 이번 달(서울 기준)로 연다.

## 4. 월별 통계 화면 (B안, 사용자 선택)

위에서 아래로 한 번에 스크롤되는 목록이다. 요약 카드와 카테고리는 목록 머리, 전체 내역이 목록 본문이다.

### 월 넘기기

- 맨 위 `‹ {YYYY}년 {M}월 ›`. `‹`는 이전 달, `›`는 다음 달.
- 이번 달에서는 `›` 비활성, 2000년 1월에서는 `‹` 비활성. 미래 월로 갈 수 없다.
- 월을 바꾸면 통계와 내역을 둘 다 처음부터 다시 불러온다(내역 커서 버림). 늦게 온 이전 달 응답은 버린다.
- 화살표 버튼 접근성 이름: "이전 달", "다음 달"(내 판단).

### 요약 카드

- 라벨 "총 지출", 금액을 가장 크게("26,000원").
- 그 아래 세 칸: **건수**("4건"), **사용률**("8.6%", 소수부가 0이면 ".0" 숨김: 기존 홈의 `formatUsagePercent`), **남은 예산**("274,000원").
- 예산을 넘은 달(`budgetBalanceAmount < 0`): 세 번째 칸 라벨을 "초과"로 바꾸고 절댓값("12,000원")을 보인다. 0이면 "남은 예산 0원"(내 판단).
- 예산이 없는 달(`budgetAmount: null`): 사용률·남은 예산 칸 값이 "미설정". 총 지출·건수는 그대로.

### 카테고리

- 섹션 라벨 "카테고리".
- 한 줄 가로 막대를 `sharePercent` 비율로 나눠 칠한다. 범례 행마다 색 점·카테고리 이름·"{금액}원 · {비중}%".
- 순서는 서버 응답 그대로(금액 내림차순, 동률은 고정 코드 순서). 최대 7개라 일반 세로 배치.
- 색은 카테고리 코드마다 고정(같은 카테고리는 어느 달에서나 같은 색). 7색 팔레트는 구현자 판단, 파란 계열 기존 색(`#208AEF`)과 어울리게.
- 지출 0건: 막대·범례 대신 "이 달에는 기록한 지출이 없어요".

### 전체 내역

- 섹션 라벨 "전체 내역". 기존 이번 달 내역과 같은 행(`ExpenseRow`, 접근성 이름 "{제목}, {보조}, {금액}"), 같은 무한 스크롤(`useMonthExpenses`, 20건)과 상태 표시(추가 로딩·추가 실패 다시 시도·"모든 내역을 불러왔어요").
- "지출 기록하기" 버튼은 **이번 달을 볼 때만** 내역 섹션 위에 둔다(내 판단). 지난달에 기록하려면 입력 화면에서 날짜를 고른다.
- 지출 0건이면 빈 내역 문구는 따로 보이지 않는다(카테고리 자리의 안내로 충분).

### 불러오기 상태

| 상태 | 표시 |
|---|---|
| 첫 로딩(통계 또는 첫 내역 페이지) | 월 넘기기 아래 가운데 로딩. 월 넘기기는 계속 보이고 누를 수 있다 |
| 통계 또는 첫 내역 페이지 실패 | 월 넘기기 아래 연결 오류 문구 + "다시 시도"(둘 다 다시 불러옴) |
| 화면에 돌아옴(포커스) | 보던 달의 통계와 내역을 다시 불러온다 |

통계와 첫 내역 페이지는 동시에 요청한다(내 판단, 아래 모두).

- **둘 다 성공해야** 화면을 보인다. 하나만 먼저 와도 로딩을 유지한다. 둘 중 하나라도 실패하면 오류 상태다(반쪽 화면을 보여 주지 않는다).
- 월을 바꾸면 이전 달 내용을 즉시 지우고 로딩을 보인다. 이전 달 숫자가 새 달 이름 아래 남지 않게 한다.
- 포커스 시 다시 불러오기도 같은 로딩을 거친다(기존 이번 달 내역과 같은 동작. 깜빡임 개선은 이번 범위 밖).
- 요약의 건수와 내역 개수가 두 요청 사이의 변경 때문에 잠깐 어긋나는 것은 허용한다. 다음 포커스에서 맞춰진다.

### 월 상태와 뒤로 가기

- 보는 달은 통계 화면의 **화면 안 상태**다. 월을 넘겨도 스택에 화면이 쌓이지 않는다. 통계 화면에서 뒤로 가면 몇 달을 넘겼든 홈이다.
- 화면은 선택적 월 파라미터를 받을 수 있다(수정 뒤 이동용, 5절). 파라미터가 오면 그 달로 상태를 바꾼다.
- "이번 달"과 "오늘"은 앱에서 서울 기준으로 계산한다: 기존 `src/lib/month.ts`의 `currentMonth()`·`todayInSeoul()`(UTC+9 고정). 서버 응답의 달을 기다리지 않는다. 자정 경계에 화면을 연 채 달이 바뀌면 다음 포커스나 월 이동 때 새 기준이 적용된다.

## 5. 지출 수정과의 연결 (F-M03 미룬 부분)

- 수정 화면의 날짜 범위를 **2000-01-01 ~ 오늘(서울 기준)**로 넓힌다(입력 화면과 같음).
- "지난달 지출은 아직 고칠 수 없어요" 상태와 문구를 없앤다. 어느 달 지출이든 수정·삭제할 수 있다.
- **저장 성공**: 통계 화면으로 돌아가며 **수정된 날짜가 속한 달**을 보여 준다(문서: "수정 후 새 날짜가 속한 월의 목록으로 이동"). 같은 달이면 보던 달 그대로. 수정 화면이 저장 응답의 `expenseDate` 달을 통계 화면에 넘기고, 통계 화면은 그 달로 상태를 바꾼다(4절 "월 상태와 뒤로 가기"). 넘기는 방법(뒤로 가며 파라미터 전달, `router.dismissTo` 등)은 구현자 판단이며 Expo SDK 58 문서로 확인한다. 저장 뒤 스택은 홈 → 통계 하나여야 한다(통계에서 뒤로 한 번에 홈).
- **삭제 성공**: 보던 달 그대로 돌아간다.
- 돌아간 통계 화면은 포커스 시 다시 불러오므로 이전 달·새 달 모두 다음에 볼 때 최신이다. 현재 월이 영향받았으면 홈도 포커스 시 다시 불러온다(기존 동작).
- 서버가 400 `expenseDate`(미래 날짜 등)를 주면 기존처럼 날짜 칸 아래 메시지.

## 6. 홈 (변경)

- "이번 달 내역 보기" 링크 → "월별 통계". 누르면 이번 달 통계 화면.
- 나머지 그대로.

## 7. 구조 (구현자 판단 범위)

- API 클라이언트: `getMonthStats(month)` → `GET /months/{month}/stats`. 타입 `MonthStats`, `CategoryStat`(응답 그대로, 예산 3필드 `number | null`).
- 월 계산: `nextMonth(month)`, 이전 달은 기존 `previousMonth`. 2000-01·이번 달 경계 판단.
- 통계 불러오기 훅(월이 바뀌면 다시 요청, 늦은 응답 무시)은 기존 `useMonthExpenses`의 요청 세대 패턴을 따른다.
- 요약 카드·카테고리 막대는 컴포넌트로 분리해 단위 테스트한다.
- 기존 `expenses/index.tsx`·관련 테스트·Maestro 흐름은 새 화면에 맞게 옮기거나 고친다.
- 저장소에 `.superpowers/`(브레인스토밍·작업 기록용 로컬 폴더)를 `.gitignore`에 추가한다.

## 8. 테스트

| 대상 | 경우 |
|---|---|

| 카테고리 | 서버 순서대로 이름·금액·비중; 0건 안내; 막대 조각 비율 |

| 홈 | "월별 통계" 링크가 통계 화면으로 |
