## 1. 목표와 범위

홈에서 설정 화면을 열어 펫 종류와 이번 달 예산을 바꾸고, 로그아웃하거나 탈퇴한다. 문서 기준(`03-user-flow.md` 4절)은 다음과 같다.
- 펫을 바꾸면 현재 홈의 펫 종류만 바뀐다.
- 로그아웃하면 서버 로그인을 무효화하고 앱 토큰을 지운 뒤 로그인 화면으로 간다.
- 탈퇴는 확인을 받은 뒤 계정·지출·예산을 지우고 로그인 화면으로 간다.

**포함**

- 홈 → 설정 화면 진입점
- 펫 변경(CAT·DOG)
- 이번 달 예산 변경(현재 월만)
- 로그아웃: 서버 로그아웃, 앱 토큰 삭제, SDK 로그아웃
- 회원 탈퇴: 확인 → 서버 탈퇴 → 앱 토큰 삭제 → SDK 연결 끊기
- 로그인한 공급자 표시("카카오로 로그인됨" / "Google로 로그인됨")

**제외**

- 과거 월 예산 변경(문서 기준 금지)
- 알림·테마·앱 정보 같은 다른 설정 항목
- 펫 이미지(다음 작업)
- Android(이번에도 iOS 시뮬레이터만)
- 백엔드 변경(필요한 API가 모두 있음)

**실패로 보는 것**

- 로그아웃을 눌렀는데 서버 오류나 네트워크 문제로 로그인 상태에 갇히는 것
- 탈퇴가 서버에서 실패했는데 앱이 탈퇴된 것처럼 로그인 화면으로 보내는 것
- 탈퇴를 확인 없이 한 번 탭으로 실행하는 것
- 예산·펫을 바꾼 뒤 홈으로 돌아왔는데 이전 값이 보이는 것
- 로그아웃·탈퇴 뒤 다시 로그인했을 때 SDK가 이전 계정으로 자동 로그인돼 계정을 바꿀 수 없는 것

## 2. 사용하는 API (`docs/api-spec.md`, 백엔드 `develop` 기준)

| 동작 | API | 성공 | 비고 |
|---|---|---|---|
| 내 정보 | `GET /users/me` | 200 `{id, provider, petType}` | 설정 화면에서 공급자·펫 표시 |
| 펫 변경 | `PUT /users/me/pet` `{petType}` | 200 내 정보 | 이미 있는 `api.putPet` |
| 예산 조회 | `GET /months/{month}/budget` | 200 `{month, amount}` | 이미 있는 `api.getBudget` |
| 예산 변경 | `PUT /months/{month}/budget` `{amount}` | 200 | 이미 있는 `api.putBudget`. 현재 월이 아니면 400 `month` |
| 로그아웃 | `POST /auth/logout` `{refreshToken}` | 204 | 없거나 끝난 토큰이면 401 |
| 탈퇴 | `DELETE /users/me` | 204 | 이후 토큰은 401 |

구현 시작 전에 `bootTestRun`에서 로그아웃과 탈퇴 응답을 실제로 확인한다. 문서와 다르면 차이를 보고한다.

## 3. 동작

**진입**: 홈 상단 오른쪽에 "설정" 링크를 둔다(접근성 role `link`). 설정 화면은 헤더 "설정"과 "뒤로"가 있는 스택 화면이다(`expenses` 화면과 같은 방식). 라우트는 `src/app/settings/index.tsx`, `src/app/settings/budget.tsx`.

**설정 화면** (`GET /users/me`와 이번 달 `GET /months/{month}/budget`을 함께 불러온다)

- 로딩 중에는 로딩을, 실패하면 연결 오류와 "다시 시도"를 보여 준다(기존 `MessageView` 방식).
- **펫** 줄: "고양이"·"강아지" 두 선택지 중 현재 펫이 선택돼 있다. 다른 쪽을 누르면 바로 `PUT /users/me/pet`로 저장한다. 저장하는 동안 두 선택지를 잠그고, 실패하면 이전 선택으로 되돌리고 오류 문구를 보여 준다.
- **이번 달 예산** 줄: "{YYYY}년 {M}월 예산"과 금액("300,000원"), "변경" 버튼을 둔다. 버튼을 누르면 예산 변경 화면으로 간다.
- **계정** 줄: "카카오로 로그인됨" 또는 "Google로 로그인됨", 그 아래 "로그아웃" 버튼과 "회원 탈퇴"(빨간 글씨) 버튼.
- 설정 화면은 포커스를 받을 때마다 다시 불러온다. 그래서 예산 변경 화면에서 돌아오면 새 금액이 보인다.

**예산 변경 화면** (헤더 "예산 변경")

- 입력칸에 지금 예산을 채워 둔다. 입력 규칙과 문구는 온보딩 예산 화면과 같다(`parseBudgetInput`, `formatAmountInput`, 0원·1억 원 초과면 저장 비활성).
- "저장"을 누르면 `PUT` 후 설정 화면으로 돌아간다.
- 서버가 400 `month`를 돌려주면(화면을 연 사이 달이 바뀜) `refreshStage()`로 단계를 다시 판정한다. 온보딩 예산 화면과 같은 처리다. `amount` 필드 오류는 그 문구를, 그 밖의 오류는 `errorMessage`를 보여 준다.
- 온보딩 예산 화면과 입력·검증 UI를 공유하는 컴포넌트로 뽑는다. 단, "지난달 예산 제안"은 온보딩에만 둔다.

**홈 갱신**: 홈은 이미 포커스를 받을 때마다 다시 불러온다. 설정에서 펫이나 예산을 바꾸고 돌아오면 새 값이 보인다. 추가 작업은 없다.

**로그아웃** (확인 창 없이 바로 실행. 되돌리기 쉬운 동작이기 때문이다)

1. 버튼을 잠그고 로딩을 보여 준다.
2. 서버 `POST /auth/logout`을 보낸다. **실패해도 계속한다.** 401, 네트워크 오류, 시간 초과 모두 해당한다. 서버 세션은 다음 로그인 때 무효화되거나 30일 뒤 만료된다.
3. 앱 토큰을 지운다.
4. SDK 로그아웃을 시도한다. 카카오 `logout()`, 구글 `signOut()`을 **로그인한 공급자에 대해서만** 부르고, 실패는 무시한다.
5. 세션 상태를 `signedOut`으로 바꾸면 로그인 화면으로 이동한다.

**회원 탈퇴**

1. 확인 창을 띄운다(`Alert.alert`). 제목 "회원 탈퇴할까요?", 본문 "지출과 예산 기록이 모두 삭제되고 되돌릴 수 없어요.", 버튼 "취소"(cancel)와 "탈퇴"(destructive).
2. "탈퇴"를 누르면 `DELETE /users/me`를 보낸다. **실패하면 멈춘다.** 오류 문구를 보여 주고 로그인 상태를 유지한다. 시간 초과도 실패로 본다. 이때 문구는 "탈퇴됐는지 확인하지 못했어요. 다시 시도해 주세요."다. 이미 탈퇴된 상태에서 다시 시도하면 401이 오는데, 이 경우는 기존 세션 만료 흐름대로 로그인 화면으로 간다.
3. 성공하면 앱 토큰을 지우고, SDK 연결 끊기를 시도한다. 카카오 `unlink()`, 구글 `revokeAccess()`를 로그인한 공급자에 대해서만 부르고, 실패는 무시한다. 그다음 `signedOut`으로 바꾼다.
- 카카오는 서비스 탈퇴 때 연결 끊기를 하도록 안내한다. 구글은 접근 권한을 철회해 다음 로그인 때 계정을 다시 고르게 한다.

**가짜 로그인 모드**: SDK를 쓰지 않았으므로 SDK 로그아웃·연결 끊기는 부르지 않는다. 판단 기준은 `getSocialCredential`과 같다(`__DEV__ && devLoginId`). 서버 호출과 토큰 삭제는 똑같이 한다.

## 4. 구조

- `src/api/client.ts`
  - `logout(): Promise<void>`: 저장된 리프레시 토큰으로 `/auth/logout`을 보낸 뒤 결과와 관계없이 토큰을 지운다. 토큰이 없으면 요청 없이 지운다.
  - `deleteMe(): Promise<void>`: `DELETE /users/me`. 성공했을 때만 토큰을 지운다.
  - `onSessionExpired`는 부르지 않는다. 화면 전환은 세션 provider가 한다.
- `src/session/social-credential.ts`(또는 같은 폴더의 새 파일): `signOutSocial(provider: Provider, isDev?, devId?)`와 `unlinkSocial(provider: Provider, isDev?, devId?)`. 둘 다 SDK 오류를 삼키고, 가짜 로그인 모드에서는 아무것도 하지 않는다.
- `src/session/session-provider.tsx`: 컨텍스트에 `signOut(): Promise<void>`와 `deleteAccount(): Promise<void>`를 추가한다.
  - `signOut`은 실패하지 않는다.
  - `deleteAccount`는 서버가 실패하면 그 오류를 그대로 던진다.
  - 공급자는 `GET /users/me`의 `provider`(`KAKAO`·`GOOGLE`)를 쓴다. 설정 화면이 이미 불러온 값을 인자로 넘긴다.
- 로그아웃 뒤 다시 로그인했을 때는 지금과 같은 로그인 흐름을 탄다.
- 테스트에서 SDK를 모킹하는 반복(지난 작업의 후속 정리 항목)은 이번 범위가 아니다. 새 테스트도 기존 패턴대로 모킹한다.

## 5. 테스트와 검증

**Jest(`__tests__/`)**

- API 클라이언트
  - `logout`: 서버가 204를 주면 토큰을 지운다.
  - 서버가 401을 주거나 네트워크 오류가 나도 토큰을 지우고 예외를 던지지 않는다.
  - 저장된 토큰이 없으면 요청을 보내지 않는다.
  - `deleteMe`: 204면 토큰을 지운다. 500이거나 시간 초과면 토큰을 남기고 예외를 던진다.
- `signOutSocial`·`unlinkSocial`
  - 공급자별로 맞는 SDK 함수만 부른다.
  - SDK 오류를 삼킨다.
  - 가짜 로그인 모드에서는 부르지 않는다.
- 세션 provider
  - `signOut` 뒤 `signedOut`이 된다.
  - `deleteAccount`가 실패하면 상태가 `signedIn`으로 남는다.
- 설정 화면
  - 공급자 문구와 현재 펫 선택이 보인다.
  - 다른 펫을 누르면 `putPet`을 부른다. 실패하면 이전 선택으로 돌아가고 오류가 보인다.
  - 예산 금액이 보인다.
  - 탈퇴를 누르면 확인 창이 뜬다. 취소하면 아무 요청도 보내지 않는다.
  - 탈퇴가 실패하면 오류 문구가 보인다.
- 예산 변경 화면
  - 현재 금액이 채워져 있다. 저장하면 `putBudget(currentMonth, amount)`를 부른다.
  - 400 `month`면 `refreshStage`를 부른다.
  - 0원이면 저장이 비활성이다.
- 온보딩 예산 화면의 기존 테스트가 공유 컴포넌트를 뽑은 뒤에도 통과해야 한다.

**시뮬레이터(Maestro, `bootTestRun` + 가짜 로그인 모드)**: 새 시나리오 `.maestro/settings/`

- `change-pet-and-budget.yaml`: 첫 로그인 직후 홈 → 설정 → 강아지로 바꿈 → 예산 변경 450,000 저장 → 설정에 450,000원 → 뒤로 → 홈에 "강아지"와 "450,000원" 반영
- `logout.yaml`: 설정 → 로그아웃 → 로그인 화면 → 같은 개발용 ID로 다시 로그인 → 홈(데이터 유지)
- `delete-account.yaml`: 설정 → 회원 탈퇴 → 취소(그대로) → 다시 회원 탈퇴 → 탈퇴 → 로그인 화면 → 같은 개발용 ID로 다시 로그인 → 펫 선택 화면(새 계정)
- README의 시나리오 표에 세 줄을 더한다.

**실제 로그인 모드(손으로, `bootRun`)**

- 카카오 로그인 → 로그아웃 → 다시 카카오 로그인 → 카카오 로그인 창이 다시 뜨는지(자동 로그인되지 않는지)
- 구글도 같은 방식으로 확인한다.
- 탈퇴는 실제 계정 하나로 확인한다. 카카오 연결 끊기 뒤 다시 로그인하면 동의 화면이 다시 나와야 한다.
- 이 확인은 사용자 손이 필요하다. 사용자가 할 수 없으면 PR에 "미확인"으로 적는다.

**필수 검사**: `npm run lint`, `npm run typecheck`, `npm test`, `npx expo export --platform ios`.

## 6. 구현자에게 맡기는 것

- 설정 화면의 세부 배치와 스타일(기존 카드 스타일 `#F5F7FA`, 둥근 모서리 16을 따른다)
- 공유 예산 입력 컴포넌트의 이름과 경계
- 설정 화면에서 내 정보와 예산을 불러오는 방식(훅으로 뺄지 여부)
- 펫 선택지를 온보딩 펫 화면과 공유할지 여부
