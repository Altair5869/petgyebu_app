## 1. 목표와 범위

사용자는 **월말에 카테고리별로 얼마나 썼는지 확인할 때**(사용자) 월별 통계 화면을 연다. 이때 가장 알고 싶은 것은 **목표 대비 얼마나 남았는지**다(사용자). 목표는 **달 초에 정해 두고 가끔 고친다**(사용자).

**포함**

- 월별 통계 화면에 "카테고리 목표" 카드 추가(B안, 사용자 선택)
- 목표를 한 화면에서 모두 입력하고 한 번에 저장하는 화면(A안, 사용자 선택)
- 통계 화면 요약 카드에서 그 달 예산 넣기·고치기. 과거 월과 이번 달 모두(사용자 결정)
- 카테고리를 누르면 그 달 그 카테고리 지출만 보는 화면(사용자 동의)
- API 클라이언트·타입: 과거 월 예산 PUT(경로는 기존과 같음), 목표 GET/PUT/DELETE, 지출 목록 `category` 필터
- 앱 문서에 F-M08·과거 월 예산·API 17~19번 반영

**제외**

- 예산 삭제(서버에 없음), 목표 이월·알림·푸시(서버에 없음)
- 인사이트 화면에서 카테고리 누르기(사용자 동의: 주 단위 화면에 달 단위 목록을 붙이면 숫자가 맞지 않아 헷갈림)
- 과거 월 펫 표시(기존 규칙 그대로 없음)
- 앱에서 남은 금액·사용률을 다시 계산하는 것. 서버 값을 그대로 쓴다(입력 화면의 "더 정할 수 있는 금액" 미리보기만 예외, 4-3)

**실패로 보는 것**

- 목표를 넘은 카테고리가 "-12,000원 남음"처럼 보이는 것(초과는 "12,000원 초과")
- 목표 저장 중 일부만 저장됐는데 사용자가 모르는 것, 또는 다 저장된 것처럼 화면을 닫는 것
- 사용자가 고르지 않은 순서 때문에 목표 저장이 409로 실패하는 것(4-4 순서 규칙이 막아야 함)
- 예산·목표·지출을 바꾸고 돌아왔는데 통계 화면의 목표 숫자가 예전 그대로인 것
- 과거 월 예산을 넣었는데 홈·펫이 바뀌는 것(바뀌면 안 됨, 서버가 보장하지만 앱도 현재 월 외에 홈을 건드리지 않음)

| 11월·12월 예산 GET·PUT | 400 `month` "2000-01부터 현재 월까지만 허용합니다." |

- 통계 GET은 예산이 없는 달에도 200이다(`budgetAmount`·`usagePercent`·`budgetBalanceAmount`만 `null`, `categories`는 그대로). 목표의 `spentAmount`는 통계의 카테고리 `spentAmount`와 같은 값이다(계약, 위 9월 응답에서 CAFE 70,000·FOOD 3,000으로 일치 확인).

붙여 받은 계약과 모두 일치한다. 줄이는 PUT도 결과 합이 예산을 넘으면 409라는 점 때문에 저장 순서 규칙(4-4)이 필요하다.

## 3. 화면 이동

```
월별 통계 ─"고치기 ›"/"목표 정하기"──▶ 카테고리 목표 입력 ──저장──▶ 월별 통계
월별 통계 ─"넣기 ›"/"고치기 ›"/"9월 예산 넣기"──▶ 예산 입력 ──저장──▶ 월별 통계
월별 통계 ─목표 카드 줄 / 비율 카드 줄──▶ 카테고리 지출 ──줄──▶ 지출 수정
```

- 새 화면 두 개(목표 입력, 카테고리 지출)는 `stage === 'ready'` 보호 그룹에 추가한다. 헤더 표시, 뒤로 라벨 "뒤로". 헤더 제목은 "카테고리 목표", "카테고리 지출"(내 판단). 어느 달·카테고리인지는 본문 제목에 쓴다.
- 달·카테고리는 화면 파라미터로 넘긴다. 형식이 틀리거나 범위 밖(2000-01 ~ 현재 월, 카테고리 7개 값)이면 "잘못된 접근이에요"와 "뒤로" 버튼만 보인다(내 판단).
- 예산 입력은 기존 설정의 예산 화면을 달 파라미터를 받도록 넓혀 같이 쓴다(5절). 파라미터가 없으면 지금처럼 현재 월이다.
- 파일 위치·이름은 구현자 판단(예: `src/app/goals.tsx`, `src/app/expenses/by-category.tsx`). `expenses/[id]`와 겹치지 않게 한다.

## 4. 화면

### 4-1. 월별 통계 화면 바뀌는 점

위에서 아래로: 달 선택 → 요약 카드(+예산 줄) → **카테고리 목표 카드(새로)** → 카테고리 비율 카드(줄 누르기 추가) → "지출 기록하기"(이번 달만) → 전체 내역.

**요약 카드 예산 줄**

- 카드 맨 아래 구분선 아래 한 줄: 왼쪽 "9월 예산 **300,000원**", 오른쪽 "고치기 ›". 예산이 없으면 "9월 예산 **미설정**", 오른쪽 "넣기 ›".
- 달 이름은 앞 0 없이 "9월"(이번 달도 같은 모양, 사용자 결정).
- 누르면 예산 입력 화면을 그 달로 연다.

**카테고리 목표 카드** (흰 카드, 제목 "카테고리 목표")

| 상황 | 내용 |
|---|---|
| 예산 없음(`budgetAmount: null`) | 문장 "목표를 정하려면 이 달 예산이 먼저 있어야 해요." + 주 버튼 "9월 예산 넣기" → 예산 입력 |
| 예산 있음, 목표 없음 | 문장 "이 달에 정한 목표가 없어요." + 보조 버튼 "목표 정하기" → 목표 입력 |
| 목표 있음 | 제목 옆 "고치기 ›" → 목표 입력. 목표 줄들 |
| `goalsExceedBudget: true` | 목표 줄 위에 빨간 문장 "목표 합이 예산보다 커요. 목표를 줄이거나 예산을 올려 주세요." |

목표 줄(서버 순서 그대로, 목표 있는 카테고리만):

- 윗줄: 카테고리 이름 | 오른쪽에 남은 금액. `remainingAmount ≥ 0`이면 "30,000원 남음"(굵게, 기본 글자색), 음수면 "12,000원 초과"(굵게, `colors.danger`). 0이면 "0원 남음".
- 진행 막대: 길이 `min(usagePercent, 100)%`, 바탕 `colors.border`. 색은 카테고리 색(`CATEGORY_COLORS`), 초과면 `colors.danger`로 꽉 참.
- 아랫줄(작게, `colors.muted`): "120,000원 / 목표 150,000원" (`spentAmount` / `goalAmount`).
- 줄 전체를 누르면 카테고리 지출 화면(그 달·그 카테고리).
- 접근성: 줄 하나로 읽는다. 예: "식비, 목표 150,000원 중 120,000원 썼어요, 30,000원 남았어요" / "…12,000원 넘었어요"(내 판단). 역할은 버튼.

**카테고리 비율 카드**: 모양은 그대로. 각 카테고리 줄을 누르면 카테고리 지출 화면. 오른쪽 끝에 작은 "›" 표시(내 판단). 접근성 라벨은 지금 문구 유지 + 역할 버튼.

**불러오기·갱신**

- 통계, 전체 내역, 목표를 함께 불러온다. 셋 중 하나라도 실패하면 지금처럼 `CONNECTION_ERROR`와 "다시 시도"(셋 다 다시). 셋이 모두 그 달 응답으로 준비돼야 내용을 보인다(내 판단: 기존 방식과 같게, 늦게 온 이전 달 응답은 버림).
- 화면에 들어올 때·돌아올 때·달을 바꿀 때마다 다시 불러온다(기존 `useFocusEffect` 그대로). 예산·목표·지출을 바꾸고 돌아오면 이것으로 갱신된다.

### 4-2. 예산 입력 화면 (기존 설정 예산 화면 확장)

- 본문 제목 "2026년 9월 예산"(기존 `monthTitle`). 헤더 제목은 기존 "예산 변경" 그대로.
- 처음에 그 달 예산을 불러와 채운다. 없으면 빈 칸.
- 저장하면 그 달로 PUT하고 뒤로 간다. 통계 화면이 돌아올 때 다시 불러온다.
- 현재 월에서 `month` 오류가 나면(자정에 달이 바뀐 경우) 기존처럼 `refreshStage`를 부른다. 과거 월에서 `month` 오류는 서버의 필드 문구를 그대로 보인다.
- 이번 달 예산을 여기서 바꿔도 따로 할 일은 없다. 홈은 돌아올 때마다(`useFocusEffect`) 다시 불러오므로 펫·금액이 갱신된다(설정 예산 화면과 같음).
- 설정 화면의 "변경" 버튼은 파라미터 없이 지금처럼 현재 월을 연다.
- 예산을 목표 합보다 낮추는 것은 막지 않는다(서버도 허용). 돌아오면 목표 카드의 초과 안내가 보인다.

### 4-3. 카테고리 목표 입력 화면 (A안)

- 본문 제목 "2026년 10월 카테고리 목표".
- 맨 위 강조 상자(`colors.secondary`): "예산 500,000원 · 목표 합 280,000원" / "더 정할 수 있는 금액 **220,000원**".
  - 목표 합과 더 정할 수 있는 금액은 **지금 입력된 값**으로 바로 다시 계산한다(빈 칸·잘못된 칸은 0으로 셈).
  - 더 정할 수 있는 금액이 음수면 그 자리에 "예산보다 **30,000원** 많아요"(빨강).
- 7개 카테고리 줄을 고정 순서(FOOD, CAFE, TRANSPORT, SHOPPING, HEALTH, LIVING, OTHER)로 한 카드에: 색 점 | 이름 | 금액 칸(숫자 키패드, 천 단위 쉼표, 빈 칸 안내 "목표 없음").
  - 처음 값은 서버 목표. 칸을 비우면 그 목표를 지운다.
  - 칸 아래 오류: 0이거나 1억 원 초과면 "1원 이상 1억 원 이하로 입력해 주세요"(문구는 기존 금액 입력 문구와 맞춤, 구현자 판단).
  - 줄 접근성 라벨: "식비 목표 금액".
- 아래 주 버튼 "저장".
  - 바뀐 칸이 없거나, 잘못된 칸이 있거나, **입력된 목표 합이 예산보다 크면 누를 수 없다**(내 판단, 아래 "사용자 확인" 참고).
  - 저장 중에는 버튼이 불러오는 중 표시이고 칸은 잠긴다.
- 예산이 없는 달로 들어온 경우(다른 기기에서 바뀐 경우 등): "목표를 정하려면 이 달 예산이 먼저 있어야 해요." + "9월 예산 넣기" 버튼만.
- 들어올 때 `goalsExceedBudget: true`면 상자 위에 통계 화면과 같은 빨간 안내. 저장하려면 합을 예산 이하로 줄이거나 칸을 비워야 한다.
- 불러오기 실패: `CONNECTION_ERROR`와 "다시 시도". 저장 실패는 4-4.

### 4-4. 목표 저장 규칙 (내 판단, 사용자에게 설명함)

서버는 카테고리마다 따로 PUT·DELETE를 받고, **매 요청의 결과 합이 예산 이하여야** 한다(줄이는 PUT 포함). 그래서 앱이 순서를 정한다.

1. 저장을 누르면 **먼저 목표를 다시 GET** 해서 서버의 지금 값(예산·목표)을 기준으로 삼는다(다른 기기 변경·이전 실패 반영). 이 GET의 예산으로도 입력 합 ≤ 예산인지 다시 본다. 넘으면(다른 기기에서 예산을 낮춘 경우) 아무것도 보내지 않고, 입력을 그대로 둔 채 화면 아래 오류 문장으로 "목표 합이 예산보다 커요. 목표를 줄이거나 예산을 올려 주세요."를 보이며 상자의 예산 숫자도 새 값으로 바꾼다. 저장 버튼을 막아 두므로 3의 409는 동시 변경 같은 드문 경우의 대비이며 따로 화면을 만들지 않는다.
2. 서버 값과 입력 값을 비교해 바뀐 카테고리만 순서대로 보낸다. 순서는 순수 함수로 만들고 Jest로 검증한다(예: `planGoalSaves(current, desired, budget) → 작업 목록`).
   - ① 비운 칸: DELETE.
   - ② 줄인 칸(고정 순서대로): 그 PUT 뒤 합이 예산 이하면 PUT. 아니면 **DELETE를 먼저** 하고, 그 카테고리의 PUT은 ③ 맨 앞으로 미룬다.
   - ③ 미룬 PUT, 그다음 늘리거나 새로 넣은 칸 PUT(고정 순서대로).
   - 입력 합 ≤ 예산이면 이 순서에서는 매 단계 합이 예산 이하라 서버 거절이 없다.
3. 하나라도 실패하면 **거기서 멈춘다.** 목표를 다시 GET 해서 서버 값과 입력이 다른 칸을 빨갛게 표시하고 "저장되지 않았어요"를 칸 아래에 둔다. 입력은 그대로 둔다. ②에서 DELETE한 뒤 ③의 PUT이 실패하면 서버에는 그 목표가 잠시 없지만, 칸에는 사용자가 입력한 새 값이 남고 "저장되지 않았어요"로 표시되므로 다시 저장하면 넣어진다(받아들일 수 있는 위험으로 판단). 화면 아래 오류 문장:
   - 409 `CATEGORY_GOALS_EXCEED_BUDGET`·`BUDGET_REQUIRED`: 서버 `message`
   - 400 필드 오류: 그 칸 아래에 서버 필드 문구
   - 그 밖(연결·시간 초과 포함): 기존 `errorMessage`
   - 다시 GET도 실패하면 칸 표시 없이 오류 문장만. 다시 "저장"을 누르면 1부터 다시 해서 남은 것만 보낸다(시간 초과로 이미 반영된 요청도 1의 GET이 걸러 낸다).
4. 모두 성공하면 뒤로 간다. 통계 화면이 다시 불러온다.

### 4-5. 카테고리 지출 화면

- 본문 맨 위: 제목 "10월 카페", 큰 금액 "62,000원"(그 달 그 카테고리 `spentAmount`, 통계 응답의 카테고리 값. 없으면 0원).
- 그 카테고리에 목표가 있으면 아래 줄: "목표 50,000원 · 12,000원 초과"(초과는 빨강) 또는 "목표 150,000원 · 30,000원 남음".
- 아래 목록: 전체 내역과 같은 줄 모양(`ExpenseRow`), 더 불러오기·"다시 시도"·"모든 내역을 불러왔어요"·빈 상태 "이 달에 이 카테고리 지출이 없어요"(내 판단).
- 필터 목록은 `GET /months/{month}/expenses?category=...`. 다음 페이지는 같은 `category`와 `cursor`를 함께 보낸다. 이 화면은 달·카테고리가 고정이라 필터를 바꾸는 일은 없다.
- 화면에 들어올 때·돌아올 때 통계·목표·목록을 다시 불러온다(셋 중 실패 시 통계 화면과 같은 오류 처리).
- 줄을 누르면 지출 수정. 지출 수정 화면은 지금 저장 후 통계 화면으로 돌아가므로(`dismissTo('/expenses', month)`), **이 화면에서 연 경우**(지출 수정 경로에 `from=category` 같은 파라미터를 붙여 알린다)에는 달이 그대로면 이 화면으로 돌아오고(뒤로), 달이 바뀌었으면 지금처럼 통계 화면 새 달로 간다(내 판단). 삭제는 지금도 뒤로 가므로 그대로.

## 5. 코드 구조 (구현자 판단, 기존 패턴 따름)

- `src/api/types.ts`: `CategoryGoal`, `CategoryGoals`, `CategoryGoalSaved`. `budgetAmount: number | null`.
- `src/api/client.ts`: `getCategoryGoals(month)`, `putCategoryGoal(month, category, amount)`, `deleteCategoryGoal(month, category)`, `getMonthExpenses(month, cursor?, category?)`(category가 있으면 `&category=`). 기존 `putBudget`은 그대로 과거 월에도 쓴다.
- 훅: 목표 불러오기는 `useMonthStats`와 같은 세대 방식. `useMonthExpenses`는 선택 `category`를 받아 커서와 함께 보낸다(바뀌면 첫 페이지부터, 기존 reload 규칙).
- 순수 함수(`src/lib/`): 목표 줄 문구(남음/초과), 막대 비율, 입력 합·더 정할 수 있는 금액, 저장 작업 순서(`planGoalSaves`), 달 이름("9월").
- 화면 구성 요소는 `src/components/`(예: `category-goals-card.tsx`). 이름·색은 `CATEGORY_LABELS`·`CATEGORY_COLORS` 재사용.
- 설정 예산 화면(`src/app/settings/budget.tsx`)은 선택 `month` 파라미터를 받는다(검사는 통계 화면의 `validMonthParam`과 같은 규칙, 공용 함수로 빼도 됨).

## 6. 정한 것 중 사용자 확인이 필요할 수 있는 것

- **입력 합이 예산보다 크면 저장 버튼을 막는다.** 대화에서는 "막지 않고 서버에 맡긴다"고 했지만, 서버 확인 결과 그 경우 한 요청 이상이 반드시 거절되고 앞 요청은 이미 저장돼 일부만 바뀐다. 그래서 막는 쪽으로 바꿨다. 상자에 "예산보다 N원 많아요"가 보이므로 이유는 알 수 있다.
