# 고양이 상호작용 실험 01

상태: **사용자 프레임 확인 완료 / 홈 화면 PNG 적용 완료**.
이 폴더는 승인한 프레임의 재생성과 비교에 사용하는 별도 미리보기다. API와 연결하지 않는다.
앱 적용 내용과 검증 결과는 프로젝트 루트 `README.md`의 "홈 고양이 상호작용"을 따른다.
아래의 확인 대기·미적용 문구는 각 수정 단계 당시의 조사 기록이다. 최종 볼 경계 수정은 사용자가 확인했고, 동일 합성 결과를 PNG 12개로 내보내 홈에 적용했다.

## 볼터치 겹침 수정

- 추가 사용자 보고: 주의 상태의 감은 눈에서 화면 오른쪽 볼 겹침이 남음. 해당 눈 추출 범위에 분홍 볼뿐 아니라 주황색 볼 무늬와 진한 얼굴 윤곽까지 들어 있었다. 예를 들어 소재 `(1685,490)`의 주황색이 원본의 밝은 피부 `(276,186)`에, 소재 `(1695,530)`의 진한 윤곽이 원본 피부 `(280,204)`에 들어간다. 기존 분홍색 판별로는 제거되지 않는다.
- 주의·감은 눈에만 오른쪽 아래 경계를 추가했다. 원본 좌표의 `x + 0.55y = 374~376`에서 부드럽게 원본 볼로 이어지게 하며, 원래 눈 테두리와 새 감은 눈 선은 이 경계 안쪽에 남긴다. 다른 상태와 반쯤 감은 눈은 기존 합성 그대로다.
- 회귀 검사에서 기존 코드가 주황색 중복을 남겨 실패하는 것을 확인했다. 보정 후 주황 무늬·얼굴 윤곽 복원, 원래 뜬 눈 테두리 미복원, 감은 눈 선 유지를 원본 크기와 미리보기 2배 크기로 검사했다. 실제 사용자 화면의 증상과 최종 자연스러움은 스크린샷/사용자 재확인 대기다.
- 사용자 확인: 눈가 잔선은 사라졌지만, 눈을 감을 때 볼터치가 겹쳐 보임.
- 원인 확인: 네 상태의 눈 소재 추출 범위 아래쪽에 생성된 볼 색이 포함돼 있었다. 원본 볼과 위치가 달라 합성하면 일부가 가려지고 다른 위치에 볼 색이 추가된다. 단순히 범위를 줄이면 뜬 눈 테두리가 다시 드러날 수 있다.
- `eye-compositor.js`: 로딩할 때 눈 소재 아래쪽의 볼 색을 주변의 밝은 피부색으로 채운다. 투명도를 낮추지 않아 원래 눈 테두리가 다시 비치지 않는다. 그다음 원본 볼터치의 RGBA를 완성 프레임에 복원한다. PNG 원본 파일은 수정하지 않았다.
- 기존 눈 영역 마스크, 눈 선, 고양이 위치, 반응 시간과 상태 복귀는 유지한다. 픽셀 처리는 프레임 준비 시에만 수행한다.
- 실제 네 상태 PNG로 소재의 볼 색 제거, 눈 선·알파 유지, 원본 볼 색 복원, 원래 진한 눈 테두리 미복원을 검사한다. 브라우저의 보간·합성 결과와 피부 경계의 자연스러움은 사용자 확인 대기다.
- 미리보기 상단에 **원본 볼터치를 고정한 수정본입니다**가 표시되는지 확인하고, **원본 겹쳐 비교**를 끈 상태에서 세 정지 프레임과 쓰다듬기를 비교한다.

## 이전: 눈가 잔선 수정

- 사용자 확인: 네 상태 모두 감은 눈 주변의 테두리가 주름처럼 보임.
- 원인 확인: 기존 타원 마스크가 뜬 눈의 전체 윤곽을 덮지 못했다. 원본 RGBA 픽셀을 분석하니 각 눈 영역에서 진한 픽셀 18~129개가 타원 가장자리 또는 밖에 있어 완전히 가려지지 않았다.
- 수정: 원래 눈 영역 전체는 불투명하게 덮고, 원본 기준 3px의 바깥 피부 여백에서만 가로·세로 투명도를 완화한다. 감은 눈 소재의 위치와 배율은 유지한다.
- 눈을 감는 선·원본 눈썹은 유지하고, 뜬 눈의 잔여 윤곽을 없애는 수정이다. 눈·몸 전체를 움직이는 효과는 추가하지 않았다.
- 확인 시 **원본 겹쳐 비교**를 끈다. 이 비교 옵션은 의도적으로 뜬 눈을 겹쳐 표시한다.
- 회귀 검사는 눈 영역의 네 모서리까지 불투명 구간에 포함되는지, 피부 여백과 원본 위치가 유지되는지 확인한다. 사용자가 잔선이 사라진 것을 확인했다.

## 현재: 표정 프레임 개선 v2

안정·주의·경고·예산 도달 **네 상태 모두 새 눈 소재를 적용**했다. 원본 고양이의 몸·머리·눈썹·입은 그대로 유지하며 사용자 화면 확인을 기다린다.

- 각 상태의 반쯤 감은 눈·감은 눈 소재를 `imagegen` 내장 도구로 생성했다. 과장된 웃는 눈 대신 편안하게 감은 선을 요청했다. 기존 4×4 시트는 재생 경로에서 제거했다.
- 아래 소재 파일은 눈 부분만 사용하는 공급원이다. 생성된 몸이나 입은 사용하지 않는다.

| 상태 | 소재 파일 | 실제 크기 | 생성 프롬프트 |
|---|---|---|---|
| 안정 | `cat-stable-blink-source-v2.png` | 2014×780 | `generation-prompt-stable-v2.txt` |
| 주의 | `cat-caution-blink-source-v2.png` | 2016×780 | `generation-prompt-caution-v2.txt` |
| 경고 | `cat-warning-blink-source-v2.png` | 2014×781 | `generation-prompt-warning-v2.txt` |
| 예산 도달 | `cat-budget-reached-blink-source-v2.png` | 2014×781 | `generation-prompt-budget-reached-v2.txt` |

- 로딩할 때 원본 고양이 위에 눈 소재만 합성한 **744×576 전체 프레임**을 Canvas 메모리에 준비한다. 재생은 눈 뜸·반쯤 감음·감음 프레임 선택 방식이다. 별도 눈·눈꺼풀 리깅이 아니며, 완성 PNG 파일을 새로 내보낸 것도 아니다.
- 눈 영역 전체를 덮고 그 바깥 피부 여백 3px에서만 투명도를 완화한다. 초기 v2의 타원 마스크는 위 눈가 잔선 수정으로 교체했다. 몸·머리 윤곽·발·꼬리는 원본을 유지한다.
- 아래 **멈춰서 비교해 보세요**에 세 프레임을 나란히 표시한다. 예산 상태를 바꾸면 비교 프레임도 함께 바뀐다.
- 실제 브라우저에서의 경계·색 연결과 표정은 **사용자 확인 대기**다. 코드 검사만으로 자연스러움을 승인하지 않는다.

## 이전: 위치 고정 수정

사용자 확인에서 클릭 중 고양이가 위로 올라갔다가 복귀하는 문제가 보고됐다. 기존 렌더러가 원본 전체와 여백·비율이 다른 동작 시트 전체를 교체하는 것이 원인이었다.

- 원본 고양이를 모든 프레임에서 같은 좌표·크기로 먼저 그린다.
- 동작 시트에서는 눈 주변 두 영역만 가져와 원본 눈 좌표에 클리핑한다. 몸통·발·꼬리·머리 윤곽·입은 교체하지 않는다.
- 쓰다듬기는 고개를 기울이는 프레임을 사용하지 않고 감은 눈을 잠깐 유지한다.
- 그림 위 안내 문구는 높이를 고정해 문구 길이가 바뀌어도 그림 영역이 밀리지 않게 한다.
- 네 감정과 반응의 각 단계에서 원본 좌표 유지·눈 영역만 갱신하는 회귀 검사를 추가했다.
- 눈 주변 색 연결과 표정의 자연스러움은 실제 화면에서 사용자 재확인이 필요하다. PNG 파일 자체를 수정한 것은 아니다.

**볼 드래그는 사용자 요청이 다시 있을 때까지 보류한다. 자산 제작과 구현 모두 진행하지 않는다.**

## 열기

Antigravity 터미널의 Codex CLI 환경을 기준으로 한다. 데스크톱 앱 내장 브라우저 연결은 필요 없다.

프로젝트 루트에서 실행한다. Python 표준 라이브러리만 사용하며 패키지 설치는 필요 없다.

```bash
python3 output/cat-interaction-preview/serve-preview.py
```

Mac 브라우저에서 **http://127.0.0.1:8765/** 를 연다. 종료는 서버를 실행한 터미널에서 Ctrl+C. 포트가 사용 중이면 `--port 8766`을 붙이고 해당 주소를 연다. 서버는 미리보기와 필요한 이미지·글꼴만 제공한다.

시뮬레이터 Safari에서도 같은 주소를 직접 입력할 수 있다. 현재 부팅된 iPhone 17e에 주소를 열려면 사용자가 다음 명령을 실행한다(이 명령의 화면 결과는 아직 확인하지 않음).

```bash
xcrun simctl openurl 50047ACB-CC65-4F76-BD42-396FBB49F531 http://127.0.0.1:8765/
```

이번 수정은 Canvas 픽셀을 읽으므로 로컬 HTTP 서버에서 열어야 한다. `file://`로 직접 열면 브라우저의 Canvas 보안 정책으로 프레임 준비가 실패할 수 있다. 프로젝트 안의 상대 경로를 사용하므로 폴더만 따로 옮기지 않는다.

1. 원본 PNG와 네 가지 감정을 확인한다.
2. 각 상태에서 아래 정지 프레임 세 장을 비교한 뒤 **표정 프레임 재생**을 켠다.
3. 머리 영역을 누르거나 **머리 쓰다듬기** 버튼을 누른다.
4. **원본 겹쳐 비교**로 눈 표정의 차이를 확인한다.
5. 아래 **이번 실험에서 확인할 것**을 펼쳐 반응 중 상태 변경을 실행한다.

피드백은 `예산 상태 / 동작 / 보이는 문제` 형태로 전달한다. 예: `경고 / 쓰다듬기 종료 / 몸통이 오른쪽으로 튐`. 특히 몸통·발 위치가 튀는지, 걱정·놀람 감정이 웃는 인상으로 바뀌는지, 머리 터치 영역이 맞는지 확인한다.

## 현재 CLI 도구 확인

- `node`, `python3`, `maestro`, `xcrun` 실행 파일 확인.
- `xcrun simctl list devices booted`: 샌드박스 안에서는 CoreSimulator 연결 실패. 샌드박스 밖 조회에서는 iOS 27.0의 iPhone 18 Pro와 iPhone 17e가 Booted로 응답.
- Maestro는 실행 파일 존재만 확인했다. 실제 시나리오 실행 여부와 구분한다.
- 프로젝트에 `playwright`, `@playwright/test`, `puppeteer`는 설치돼 있지 않다. 자동 브라우저 도구를 추가하지 않았다.
- 이번 단계는 CLI 로직 검사 + 사용자의 화면 확인으로 진행한다. 자동 브라우저 검증이 필요해지면 별도 도구와 설치·브라우저 런타임 설정을 먼저 설명한다.

## 기존 자산 조사

- `assets/images/pets/cat-{stable,caution,warning,budget-reached}.png`
- 네 가지 감정 × 기본·@2x·@3x = PNG 12개.
- 각각 124×96, 248×192, 372×288. 투명 RGBA이며 애니메이션 프레임이 없다.
- @2x와 @3x는 해상도 변형이다. 눈·머리·좌우 볼 레이어가 아니다.
- 감정별 몸과 머리 자세도 다르므로 네 감정 PNG를 대기 동작 프레임처럼 반복하면 안 된다.
- `src/lib/pet-images.ts`, `src/components/pet-image.tsx`는 상태에 맞는 정지 그림을 선택한다.
- `scripts/export-pet-images.py`는 원본에서 그림으로 된 게이지를 제거하고 축소·배치하는 용도이며, 신체 부위를 분리하지 않는다.

## 가능한 효과와 필요한 그림

| 효과 | 현재 원본만으로 가능한 범위 | 필요한 보완 |
|---|---|---|
| 감정 전환 | 네 상태의 정지 PNG 교체 | 없음 |
| 이미지 전체 흔들기·확대 | 구현 가능하지만 이번 실험에 사용하지 않음 | 개별 부위 동작과 다름 |
| 눈 깜빡임 | 원본에 눈꺼풀·가려진 눈 주변이 없어 새 그림 필요 | 감정별 반쯤 감은 눈·완전히 감은 눈, 몸·얼굴 좌표 고정 |
| 머리 쓰다듬기 | 원본 전체 회전으로 대체하지 않음 | 동일 몸 자세의 접촉·반응·회복 프레임 또는 분리된 머리와 목 뒤 바탕 |
| 한쪽 볼 드래그 | 평면 PNG의 국소 워프는 기술적으로 가능하나 윤곽·인접 부위 분리가 검증되지 않음 | 깨끗한 얼굴 바탕, 윤곽을 포함한 좌우 볼, 겹침 여백, 고정점과 변형 영역 |

PNG 형식 자체가 문제는 아니다. 같은 캔버스에 정렬된 **분리 PNG 레이어** 또는 정확히 정렬된 **프레임 PNG**로도 가능하다.

볼 관련 내용은 초기 가능성 조사 기록이다. 현재 볼 드래그는 미구현이며 사용자 재요청 전까지 보류한다.

## 추가한 그림 초안의 한계

- `cat-motion-draft.png`: 원본 네 감정을 참조해 생성한 1448×1086 투명 PNG, 4열×4행.
- 행: 안정 / 주의 / 경고 / 예산 도달. 열: 눈 뜸 / 반쯤 감음 / 감음 / 쓰다듬기.
- 생성 프롬프트: `generation-prompt.txt`. 원본 파일은 덮어쓰지 않았다.
- 프레임마다 몸통·머리 위치와 비율이 조금 달라진다. 감은 눈이 경고·예산 도달에서 웃는 인상으로 보이기도 한다.
- 따라서 고양이 전체 교체용으로 **통과하지 않은 그림**이다. 초기 위치 고정 수정에서는 이 시트의 눈만 사용했지만, 현재는 네 상태 모두 개별 v2 소재로 교체했다. 이 파일은 이전 작업 기록으로만 보관한다.

## 실험 동작

- 기본은 기존 정지 원본. 초안 사용을 켠 경우에만 머리 반응과 프레임 재생을 허용한다.
- 예산 상태와 일시적인 반응을 따로 보관한다. 반응 종료 시 **가장 최근 예산 상태의 원본**을 표시한다.
- 대기 깜빡임은 4~7초 간격. 예산 도달에서는 자동 재생하지 않는다.
- 머리 누르기/버튼으로 반응하고, 손 떼기·취소·포커스 이탈 시 복귀한다.
- 시스템 동작 줄이기 설정은 자동 깜빡임을 생략하고 정지 반응만 표시한다.
- 전체 그림을 흔들거나 확대·회전하는 애니메이션은 없다. 원본에 눈 소재를 정렬해 미리 합성한 전체 프레임을 재생한다.
